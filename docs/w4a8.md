# W4FA8 MoE GEMM on M890

NoPad, Masked and Fused accept E4M3 activations with FP32 per-row scales,
naturally packed E2M1 weights and preprocessed group-32 E8M0 scales. They
accumulate in FP32 and produce BF16. N must be divisible by 64 and K by 128.
Select the input device and caller stream before invoking the APIs.

Use `preprocess_weights_and_scales(PreprocessMode.W4A8_MXFP4_MMA, False, ...)`
and apply its returned inverse scale exactly once. Every execution plan accepts
`inv_scale` (default 1, finite and positive): the epilogue forms
`effective_scale = row_scale * inv_scale` in FP32 before multiplying the accumulator.
Unit and non-unit values use separate compiled variants; non-unit values share
one variant. A scalar change never changes the execution plan.

## Configurations

Both native and streamed execution accept the same nine-element tile format:

```python
# (num_sms, block_m, block_n, block_k, warp_m, warp_n, warp_k, stages, n_expand)
tile = (39, 64, 256, 128, 64, 64, 128, 2, 1)
configs = tile
```

`full_k` retains the fragment for one WarpK slice; `rolling_k32` retains a
K32 fragment at a time. `standard`, `prefix` and `queue` describe task
assignment. A-load is derived internally: queue uses two M16 operand slots
(`ring2`), and other schedulers load the activation operand in bulk.
Supported combinations are validated together, including threads,
shared memory and compiled occupancy. Policies are not an arbitrary Cartesian
product. Rolling bulk kernels use WarpN32 at M16/M32 and WarpN64 at M64;
M16 prefix uses full fragments with WarpN64. Masked uses one `full_k/bulk/standard` kernel.

The runtime derives the execution plan from the tile. Where both
M64/WarpN64 standard fragments are supported, Fused uses `rolling_k32`.
NoPad uses `rolling_k32` for BlockN256 with K>2048 and `full_k` otherwise.
Scheduler, fragment and A-load are entirely internal and cannot be overridden.
Pass the tile directly, without a mode tag or nested wrapper. Queue tiles derive
`queue`. Other tiles derive `prefix` only for NoPad with 16–64 experts, K<=1024
and a supported prefix tile; otherwise they use `standard`. Prefix supports
M16/M32/M64 single-M-warp tiles, BlockN128/256, BK=WK128, two stages and no
N expansion, with its existing WarpN and input alignment constraints.
These fixed rules come from offline comparisons; no GPU timing occurs during
dispatch. Alignment and GEMM use the same inference rules.

For small-expert NoPad, standard retains a cursor and advances through expert
row counts as its persistent work IDs increase. Prefix builds row and M-tile
prefix sums inside each CTA and uses warp ballot/shuffle to locate the expert.
It supports nonuniform and empty experts and requires at most 64 experts.
M32 stores the prefixes in 512 bytes of shared memory with a CTA barrier;
M16 also groups the M swizzle in pairs. Other standard interfaces use their
existing schedulers and metadata paths.

The public queue plan contains one tile. Automatic routed execution uses M160
(M160/stages3 for Fused, M160/stages2 for NoPad). Other supported single queue
tiles can be specified explicitly. Dual-tile queue partitioning remains an
internal experimental implementation pending generalization; the tile-only public format cannot express multiple kernels, and automatic
selection never constructs that plan.

Streamed execution decodes bounded expert chunks into two E5M2 weight buffers
and overlaps decoding with a fixed FP8 core:

```python
configs = (deep_gemm.get_num_sms(), 256, 256, 128, 64, 64, 128, 4, 1)
```

This exact core tile selects streamed execution. Only its CU count is configurable;
other tile fields must match. The host derives decode-N slices, expert chunks,
fixed/ramp scheduling, gather and empty-expert handling internally from shapes
and device resources. These execution details are not public configuration knobs.
Each of the two weight buffers is bounded by384 MiB. Explicit configurations
must satisfy interface, alignment, workspace and device constraints; invalid
configurations fail rather than silently changing tile or execution mode.
The automatic average-row performance thresholds do not restrict explicit use,
so the tile can also be evaluated on small-M inputs. Masked does not support it.

Fused grouped activation storage is bounded
by 1 GiB. The runtime decodes weights and constructs input-dependent metadata on
every call, including Graph replay.

`configs=None` for NoPad/Masked uses deterministic host heuristics based on
shape, the expected-row hint and resource limits. There is no production GPU
timing or measured-cost cache. Explicit configs specify the complete plan and
never silently fall back. Other dtypes retain their existing configuration
formats. There is no public config query API.

## Routing layout

Call `moe_align_block_size` with the activation, packed weights and top-k expert
IDs. For W4FA8 it returns a complete config followed by the existing routing
tensors. Pass that config unchanged to Fused. To override the plan, supply it
as `config=` to alignment before producing routing metadata.

A single native Fused kernel uses its compute BlockM as the routing padding
granularity. Streamed Fused uses a routing BlockM of 64; the internal experimental dual-tile plan also uses 64.
This value is derived internally. Metadata preserves padded token offsets and
compact grouped output offsets separately. Output remains contiguous by expert,
with no routing padding. General token gather handles arbitrary token order;
there is no arithmetic-progression or uniform-routing specialization.

## Preparation and graph capture

Native warmup prepares every declared tile, supporting metadata modules and both
unit/non-unit inverse-scale variants. Prepared state is keyed by device, caller
stream, shape and complete config, and never depends on warmup row counts. Capture
on an unprepared caller or plan fails in the W4FA8 runtime before module loading.
Captured calls use loaded handles and regenerate task metadata from current inputs.

Compile-only may prepare modules, but does not establish capture readiness. Run
one ordinary warmup on the actual capture stream before capturing.

Streamed warmup additionally prepares all declared chunk and N-tail modules,
internal streams and disable-timing events for that caller. A new caller must
warm its own context; capture never changes to a native fallback. Both numerical
variants are prepared without candidate trial launches. Input-dependent metadata
and decoded weights remain per-call. Scratch is private to each call or captured
graph; the caller must serialize concurrent replays of the same graph. Fork/join
events order all internal work before subsequent caller operations.
